# 개발 로드맵

목표: "카페·식당으로 운영 중이지만 웨딩/돌상 전환 가능성이 높은 숨은 공간"을
대구·경북·부산·경남·강원에서 자동 발굴 → 점수화 → 연락 우선순위 → 엑셀/시트 출력.

진행 표기: ✅ 완료 / 🚧 골격(스텁) / ⬜ 예정

---

## Phase 0 — 프로젝트 기반 ✅
- ✅ 프로젝트 구조, 설정 체계(`config/*.yaml` + `.env`)
- ✅ 데이터 모델(Place → Analysis → Score → Record)
- ✅ 파이프라인 골격 + `--dry-run` (외부 API 없이 전 구간 검증)
- ✅ 엑셀 출력(등급 색상·우선순위 정렬·고정창)
- ✅ 규칙기반 1차 제외필터 + 단위 테스트

**산출물:** `python -m sseomlab run --dry-run` 으로 데모 엑셀 생성 가능.

## Phase 1 — 수집 파이프라인 (1단계 기능) 🚧
- 🚧 네이버 지역검색 API 수집기 (`collect/naver_local.py`) — 골격 완성, 키 연결 필요
- ⬜ 지역×공간유형 검색어 매트릭스 튜닝 (중복·노이즈 제거)
- ⬜ 수집 결과 캐시/중복제거(주소+상호 정규화), SQLite 저장
- ⬜ 수집량/커버리지 리포트 (지역별 후보 수)

**완료 기준:** 5개 지역에서 공간유형별 후보 1,000+건 무중복 수집.

## Phase 2 — 정보 보강 + 텍스트 분석 (2단계 기능) ⬜
- ⬜ 네이버 블로그 검색 API → 리뷰 텍스트/리뷰 수 보강
- ⬜ 홈페이지 HTML 파싱 → 소개·대관·주차 문구 추출
- ⬜ 인스타 '노출 강도' 추정(공개 검색 기반, 비공개·개인정보 미수집)
- ⬜ 외곽/주차/평일유휴 등 정량 신호 추출

**완료 기준:** 각 후보가 분석 가능한 `raw_text` + 신호 필드를 보유.

## Phase 3 — Claude 판정·점수화 (4·5단계 기능) 🚧
- 🚧 점수 프롬프트(`score/prompts.py`) + 스코어러(`score/scorer.py`) — 골격 완성
- ⬜ 2단계 스크리닝 실배선: haiku 1차 → opus 정밀
- ⬜ 점수 보정: Claude 정성 점수 × `config/scoring.yaml` 정량 가중 결합
- ⬜ 응답 JSON 스키마 검증/재시도(파싱 실패 시 자가수정)
- ⬜ 소량 라벨셋으로 점수 정합성 검증(사람 평가와 상관)

**완료 기준:** 100건 샘플에서 제외 정확도·등급 분포가 운영자 기대와 일치.

## Phase 4 — 사진 분석 (3단계 기능) ⬜
- ⬜ 사진 수집(`collect/enrich.enrich_with_images`)
- ⬜ Claude Vision 으로 정원/마당/테라스/오션뷰/숲/통창/룸/수용력 추출
- ⬜ 사진 신호를 wedding/dolsang 점수에 반영
- ⬜ 토큰 비용 관리(장당 리사이즈, 상위 후보만 사진 정밀)

**완료 기준:** 사진 보유 후보의 야외요소 판별 정확도 검증.

## Phase 5 — 우선순위 + 출력 (6단계 기능) 🚧
- ✅ 종합점수 기반 연락 우선순위
- ✅ 엑셀 출력
- ⬜ 구글시트 출력(`export/gsheet.py`, 서비스계정)
- ⬜ 등급별 시트 분리 / 지역별 탭
- ⬜ "연락용 카드"(상호·강점·추천 제안·연락처) 자동 생성

**완료 기준:** 운영자가 시트만 보고 바로 컨택 가능한 형태.

## Phase 6 — 운영화 ⬜
- ⬜ 증분 실행(이미 평가한 곳 skip) + 주기 배치
- ⬜ 비용/호출 로깅, 실패 복구
- ⬜ 운영자 피드백 루프(컨택 결과를 라벨로 환류 → 가중치 재학습)

---

## 권장 진행 순서
1. **Phase 1** 키 연결 → 실제 수집 데이터 확보
2. **Phase 3** 텍스트만으로 점수화 → 빠르게 우선순위 시트 1차 산출(가장 빠른 가치)
3. **Phase 2** 보강으로 정확도 향상
4. **Phase 4** 사진으로 정밀화
5. **Phase 5~6** 출력 고도화·운영화

> 텍스트만으로도 Phase 1+3 조합이면 곧바로 "연락 우선순위 엑셀"이 나온다. 사진은 정확도 향상 단계.
